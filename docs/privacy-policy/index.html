1. Application and operator

automation thread is a small development-stage application that uses the official Meta Threads API to research public posts by keyword and assist with preparing new Vietnamese-language draft posts. Its source code is maintained by the GitHub account mvtruong2008-jpg. Meta app ID: 1109750755284751.

Current scope: The application researches topics and creates drafts. If explicitly enabled by the owner and granted the Threads publishing permission, it can publish original text posts to that owner's authorized Threads account. It does not automatically reply, like, follow or sell information. The owner must authorize the API integration.

2. Information used

  • Authorized Threads account: Threads user ID, username, authorization status, and the access token required to request API data.
  • Public Threads search results: public post text, username, post ID, permalink, timestamps, and keyword-search relevance/ranking returned by Meta, when available and permitted.
  • Draft and diagnostic information: topics selected, AI-generated draft content, source references, timestamps, counts and success/error statuses.
  • Website access: This policy website has no custom account registration, analytics scripts, advertising scripts, or tracking cookies. GitHub Pages may process standard technical access information under GitHub's own policies.

We do not request your Threads password. The tool does not intentionally collect private messages, contact lists, payment details or sensitive profile attributes.

3. Why the data is used

To verify Threads API permissions; research public topic signals and permitted Threads keyword search; generate original AI-assisted draft posts; optionally publish owner-authorized posts when that workflow is enabled; check recent posts for duplicate content and posting intervals; provide troubleshooting summaries; and maintain access tokens if the owner enables token management.

4. AI services and external providers

The tool can send selected excerpts of permitted public Threads posts, topic labels and related contextual information to Google's Gemini API to generate original Vietnamese-language drafts. Do not authorize this workflow for private or confidential content. Data provided to Google is processed subject to the applicable Google API terms and privacy practices.

Meta provides the Threads API. GitHub hosts the code, Actions execution, encrypted repository secrets, draft artifacts and this website. Their respective services and policies apply. We do not sell personal information or use it for personalized advertising.

5. Storage, visibility and retention

  • Threads user access tokens are configured as GitHub Actions Secrets, not published in site content or committed source files. The authorized repository owner can replace or delete those secrets.
  • Research drafts and selected public-source references can be uploaded to GitHub Actions artifacts. The current draft workflows request artifact retention of 3 days. Because the repository is public, artifacts and run information may be accessible to others with sufficient access under GitHub's rules.
  • Workflow logs record status, timing, and aggregate diagnostics. They are subject to the repository's GitHub Actions retention settings; secrets must not be intentionally printed to logs.
  • Public posts and user content are not maintained as a separate permanent application database by the current bot. Copies already downloaded by other parties may not be recoverable or removable by this operator.

6. Data removal, withdrawal and choices

Authorized users may withdraw the application's permissions from their Threads account settings, remove or rotate tokens in their GitHub repository settings, and request deletion of any artifacts controlled by the application operator. See the Data Deletion Instructions. Revoking access may prevent automated keyword research and token refresh.

7. Security

We limit requested access to the permissions needed for research and draft generation and store credentials using GitHub Secrets. However, no internet-connected service can guarantee absolute security. Do not include tokens or private information in public GitHub Issues.

8. Changes and contact

The policy may be updated if the application's capabilities or data handling change; the updated effective date will appear here. For support, questions or data-removal requests, contact the maintainer using the project's GitHub Issues with a non-sensitive description. GitHub Issues are public, so never include account credentials, tokens, private content, or other sensitive information in the issue. The maintainer can arrange an appropriate private follow-up if needed.

1. Giới thiệu ứng dụng

automation thread là ứng dụng đang phát triển, sử dụng Threads API chính thức của Meta để nghiên cứu bài viết công khai theo từ khóa và hỗ trợ AI tạo bản nháp tiếng Việt. Mã nguồn do tài khoản GitHub mvtruong2008-jpg quản lý. Mã ứng dụng Meta: 1109750755284751.

Phạm vi hiện tại: Công cụ nghiên cứu và tạo bản nháp; khi chủ tài khoản chủ động bật chức năng đăng và Meta cấp quyền phù hợp, công cụ có thể đăng bài văn bản gốc lên chính tài khoản Threads đã ủy quyền. Không tự trả lời, thích hoặc theo dõi tài khoản khác.

2. Dữ liệu có thể xử lý

  • Định danh người dùng Threads, tên người dùng, trạng thái ủy quyền và token được chủ tài khoản cấp.
  • Dữ liệu tìm kiếm bài công khai được Meta cho phép: văn bản bài viết, tên người đăng, mã bài, đường dẫn, thời gian đăng và thứ hạng tìm kiếm nếu có.
  • Chủ đề nghiên cứu, bản nháp do AI tạo, tham chiếu nguồn, thời gian xử lý và trạng thái kỹ thuật.
  • Website này không tự triển khai công cụ phân tích truy cập, quảng cáo hoặc cookie theo dõi. GitHub Pages có thể xử lý thông tin truy cập kỹ thuật theo chính sách của GitHub.

Công cụ không yêu cầu mật khẩu Threads và không chủ động thu thập tin nhắn riêng tư, danh bạ hay thông tin thanh toán.

3. Mục đích xử lý

Xác thực quyền Threads API; tìm kiếm và đánh giá tín hiệu chủ đề công khai; dùng AI tạo bản nháp độc lập; tùy chọn đăng nội dung khi chủ tài khoản bật tính năng và cấp quyền; đọc những bài gần đây của tài khoản để chống đăng trùng và giãn cách; hiển thị chẩn đoán kỹ thuật; và gia hạn token khi chủ tài khoản bật tính năng.

4. Dịch vụ bên thứ ba

Trích đoạn của bài viết Threads công khai được phép sử dụng, nhãn chủ đề và thông tin liên quan có thể được gửi đến Google Gemini API để tạo bản nháp. Dữ liệu gửi cho Google chịu sự điều chỉnh của điều khoản và chính sách tương ứng của Google. Meta cung cấp API, còn GitHub lưu trữ mã nguồn, workflow, Secrets, tệp kết quả và website. Chúng tôi không bán dữ liệu cá nhân hoặc sử dụng dữ liệu cho quảng cáo cá nhân hóa.

5. Lưu trữ và thời hạn

  • Token được đặt trong GitHub Actions Secrets, không ghi vào mã nguồn công khai. Chủ Repository có thể thay hoặc xóa token.
  • Bản nháp và tham chiếu đến nguồn công khai có thể nằm trong GitHub Actions Artifacts, với thời hạn lưu trữ được cấu hình hiện tại là 3 ngày. Vì Repository công khai, các tệp kết quả có thể được người khác truy cập theo quyền và quy định của GitHub.
  • Log kỹ thuật chịu thời hạn lưu trữ do GitHub Actions quy định. Công cụ hiện không vận hành một cơ sở dữ liệu lưu trữ riêng vĩnh viễn các bài đăng.
  • Những bản sao đã được bên thứ ba tải xuống có thể nằm ngoài khả năng xóa của người vận hành.

6. Rút quyền và yêu cầu xóa

Bạn có thể thu hồi quyền ứng dụng trong cài đặt tài khoản Threads, xóa hoặc thay GitHub Secret, và yêu cầu người vận hành xóa các tệp kết quả do mình kiểm soát. Xem hướng dẫn xóa dữ liệu. Việc thu hồi quyền có thể khiến các chức năng tự động ngừng hoạt động.

7. Bảo mật

Ứng dụng chỉ yêu cầu quyền phù hợp với nghiên cứu và tạo bản nháp, đồng thời sử dụng GitHub Secrets cho thông tin xác thực. Không có dịch vụ trực tuyến nào bảo đảm an toàn tuyệt đối. Không cung cấp token hay dữ liệu riêng tư trong GitHub Issues công khai.

8. Liên hệ và cập nhật

Chính sách có thể được cập nhật khi ứng dụng thay đổi chức năng xử lý dữ liệu. Để liên hệ, phản hồi hoặc yêu cầu xóa dữ liệu, tạo GitHub Issue của dự án chỉ với mô tả không nhạy cảm. GitHub Issue là công khai; không đăng thông tin đăng nhập, khóa API, tin nhắn riêng tư hoặc dữ liệu cá nhân. Người quản lý có thể thống nhất kênh trao đổi riêng nếu cần.

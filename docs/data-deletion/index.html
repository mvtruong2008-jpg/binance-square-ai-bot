English

How to revoke access and delete data

  1. Withdraw Threads authorization: Open your Threads account settings, find website/app permissions or connected applications, locate the authorized developer application automation thread and remove its access. Menu names may change.
  2. Delete stored tokens: If you are the repository owner, open the repository's GitHub Actions Secrets settings and delete or rotate THREADS_ACCESS_TOKEN. Also remove THREADS_APP_SECRET and GH_SECRETS_PAT if you no longer use automated token management.
  3. Remove generated files: Draft research outputs may be available as public-repository GitHub Actions Artifacts with a configured three-day retention. A repository administrator can delete existing run artifacts sooner. Workflow logs have separate GitHub retention controls.
  4. Ask the operator to delete controlled data: Open a project GitHub Issue with the title Data deletion request — automation thread and a brief, non-sensitive description. Do not share tokens, passwords, private posts or personal identifiers in a public issue. The maintainer can arrange private follow-up when account verification is needed.

Scope: The bot currently has no separate permanent user database. Removing access and deleting the repository's controlled secrets/artifacts stops future authenticated processing. The operator cannot remove copies that other people already downloaded or records held independently by Meta, Google or GitHub.

Tiếng Việt

Cách thu hồi quyền và xóa dữ liệu

  1. Thu hồi quyền ứng dụng: Trong phần cài đặt tài khoản Threads, tìm quyền của website/ứng dụng đã kết nối và thu hồi quyền của automation thread nếu có. Tên menu có thể khác theo phiên bản.
  2. Xóa token đã lưu: Chủ Repository mở GitHub Actions Secrets, xóa hoặc thay THREADS_ACCESS_TOKEN; xóa thêm THREADS_APP_SECRET và GH_SECRETS_PAT nếu không cần tự gia hạn.
  3. Xóa bản nháp và tệp kết quả: Người quản trị Repository có thể xóa Artifacts của GitHub Actions trước hạn lưu trữ 3 ngày đã cấu hình. Log có chính sách lưu giữ riêng của GitHub.
  4. Yêu cầu người vận hành xóa dữ liệu: Tạo GitHub Issue với tiêu đề Data deletion request — automation thread, chỉ mô tả không nhạy cảm. Không đăng token, mật khẩu hay dữ liệu cá nhân vào Issue công khai. Người quản lý có thể hướng dẫn xác thực và liên hệ riêng nếu cần.

Giới hạn: Bot hiện không có cơ sở dữ liệu người dùng riêng vĩnh viễn. Xóa quyền, khóa và bản nháp trong phạm vi kiểm soát sẽ ngăn xử lý tiếp. Người vận hành không thể xóa các bản sao bên thứ ba đã tải xuống hoặc dữ liệu do Meta, Google, GitHub lưu giữ độc lập.
